## 0. Executive summary

The four quality gateways pass, but they were passing while four pages published invented
data and the live database served a policy platform that is not the Federation's.

This pass fixed **nine defects** — three of them public-facing fabrications, one a statutory
disclosure that rendered outside its own widget, one a credential-adjacent privacy leak in
the telemetry fallback, and one that made three member write paths fail silently. It also
added the gates that would have caught them: a build verifier with a payload budget, a CSP
invariant check, a compiled-secret scan, a dependency audit, and widget-bounded assertions
in the smoke suite.

The largest item is **not** fixed: the initial payload is 776 kB gzipped against a 200 kB
SOP target, because the entire thirdweb/wallet stack is `modulepreload`ed from
`index.html`. Section 3 has the extraction design. It is a wallet-layer refactor that
cannot be responsibly validated without a funded wallet, so it is staged rather than rushed.

One item needs a decision from outside engineering: **production is still serving the
2026-10-25 build**, so none of the ground-truth work — including this pass — is live.

## 3. Proposal: cut the wallet stack out of first paint

Measured today (`npm run verify:build`):

```
   640.3 kB  web3-BqK2lQee.js      <- modulepreloaded
    81.3 kB  index-*.js            <- entry
    44.7 kB  vendor-*.js           <- modulepreloaded
     9.6 kB  index-*.css
   775.8 kB  TOTAL initial
```

The cause is not `manualChunks`. It is that `main.jsx` renders `<ThirdwebProvider>` around
the whole tree, and `Navbar`, `Layout`, `PolicyCard`, `FleetMuster` and `MusterRoll` import
`thirdweb/react` hooks directly — so the chunk is in the entry graph and Rollup is right to
preload it.

Extraction, in dependency order:

1. **`WalletBridge`** — a component whose only job is to mount `<ThirdwebProvider>` plus a
   sync child that publishes `{ address, chainId, connectionStatus }` into the existing
   zustand store. Imported with `React.lazy`, mounted only when a wallet is actually wanted.
2. **Replace hook call sites with store reads.** `useActiveAccount()` → `useAppStore(s =>
   s.wallet.address)` in `Navbar`, `Layout`, `PolicyCard`, `FleetMuster`, `MusterRoll`.
3. **Make the connect affordance a two-step.** The nav renders a static “Connect Wallet”
   button; the first click loads the bridge (640 kB, once), the second opens the wallet UI.
   Passport/email-OTP stays the primary path, so the default journey never pays for it.
4. **Keep `useAPFWrite`/`useAPFContract` inside the lazy `/shop` and `/propose` chunks**,
   where the provider is guaranteed mounted by step 1.
5. **Lower the ceiling.** `scripts/verify-build.mjs --max-initial-kb` is at 850 today as a
   regression guard; target 200 and delete the `web3 preloaded` note.

Expected result: initial payload ≈ 135 kB gzip; wallet cost paid on demand.

Risk: wallet connection, chain switching and `signMessage` all cross this boundary. This
needs a manual pass against MetaMask and an embedded wallet before merge — which is why it
is a separate PR, not a rider on this one.
